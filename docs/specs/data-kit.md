## 1. Purpose, scope, out of scope

**Purpose.** One deterministic synthetic dataset from which every acceptance case AC-01..AC-27 of the matching spec, the access seed of the access spec and the demo story can be run and checked, plus a machine-readable ground-truth file the engine is scored against. Every planted link and trap is traceable to a source file and line.

| In scope                                                                                                                       | Out of scope                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| Cases, five source file kinds, seed users, case assignments, ground truth, determinism, size tiers, generator acceptance tests | Generator code (task 2.1), parsers and extraction rules (2.2), engine and API code          |
| Planted true links, traps, background noise with its own truth                                                                 | Real-world realism beyond what the engine reads (no scanned images, no OCR noise, no PDFs)  |
| Fixtures for the human decisions in AC-13..AC-16, AC-24, AC-25 (data plus a harness script, §5)                                | Devanagari digits, Hindi templates text, tuning of weights, bands or extraction rules       |

**Rule 10 (AGENT_RULES): synthetic only.** Nothing here or in generated output is real.

| Item                | Synthetic rule                                                                                                                                                                                                   |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Persons             | Names are assembled by the generator from first-name and surname pool files in `data-kit/pools/` (invented combinations); no real person, no public figure. Planted names are fixed in this spec.                  |
| Phones              | Planted values come from the block `9000000000`..`9000099999` (the range the matching spec's acceptance cases use). Noise values come from `9100000000`..`9100999999`. Never copied from any real source. Every number is invented and tied to no real record; any resemblance to an assigned number is coincidental. The generator never emits a number outside the planted list and these declared noise ranges. |
| Accounts            | 13 digits. Planted `5010000xxxxxx`; noise `5019xxxxxxxxx`. IFSC-like codes `SYNB0000nnn` and `FAKE0000nnn` only (no real bank prefix).                                                                           |
| Vehicles            | Planted plates are those named in this spec; noise plates use the unissued series letters `ZZ` (`UP32ZZ1234`).                                                                                                   |
| FIR and note text   | Written from the phrase catalogue (§4.4) over invented facts. Case numbers `SYN-...`; every FIR and notes file opens with a banner line `SYNTHETIC DATA TRACEX-SYN/1 - NOT A REAL RECORD`.                         |
| States and stations | Fictional: Northvale, Eastmark, and districts and stations in §3.                                                                                                                                                |
| Repository          | Generated output is never committed (CODEBASE_RULES "Git"); only the generator, pools, seed files and golden hashes are.                                                                                        |

## 2. Layout and conventions

```
data-kit/
  README.md                       pointer to this spec
  pools/                          first_names_*.txt, surnames_*.txt, villages.txt, towers.txt, narrative phrases (committed, synthetic)
  schema/ground_truth.schema.json  JSON Schema of §8.2 (committed)
  seed/jurisdictions.json         states, districts, stations (§3)
  seed/users.json                 seeded users, no secrets (§9)
  seed/case_assignments.csv       username,case_id (§9)
  golden/<tier>.sha256            sha256 of out/<tier>/manifest.json (committed; the only committed hash)
  out/<tier>/                     generated, git-ignored
    manifest.json                 file list with sha256 and byte size, kit version, seed, tier
    cases.csv                     case registry, baseline batch: case_id,fir_no,fir_date,station,district,state
    ground_truth.json            ground truth (§8)
    SYNTHETIC.txt                 one-line synthetic notice
    batches/b01/cases/<case_id>/  baseline files
    batches/b02/cases/<case_id>/  late-arriving files and new cases (§3.3)
```

| Convention  | Rule                                                                                                                                                                                                                                                      |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Encoding    | UTF-8, no BOM, Unicode NFC, LF line endings, no trailing spaces, file ends with one LF.                                                                                                                                                                   |
| Line number | 1-based physical line in the file, header and blank lines counted. A source reference is `{case_id, file, line}`, `file` relative to the case directory. This is the provenance unit the engine must reproduce (CODEBASE_RULES "Non-negotiable behaviours"). |
| CSV         | RFC 4180, comma, `"` quoting only when needed, header row = line 1, empty cell = unknown. Read with Python `csv`.                                                                                                                                         |
| Dates       | ISO `YYYY-MM-DD`; timestamps `YYYY-MM-DDTHH:MM:SS+05:30`. Free text may also use `DD-MM-YYYY`, `DD/MM/YYYY` and `12 April 1990`.                                                                                                                          |
| Digits      | Western digits everywhere (Devanagari digits are out of scope for 1.0).                                                                                                                                                                                   |
| Case id     | `C-` + district digit (Rivergate 1, Hillcrest 2, Lakeside 3, Rampur 4) + sequence, at least 2 digits. Sequence 01..49 is planted, 50 upward is noise (`C-150`, `C-1100`).                                                                                  |
| Load order  | Ascending `case_id` compared numerically (district digit, then sequence as an integer, so `C-150` < `C-1100`); within a case: `fir.txt`, `notes.txt`, `sdr.csv`, `cdr.csv`, `bank.csv`, then later batches by number. Entity ids increase in this order (matching spec C5).                                                                                |
| Batches     | `b01` is the baseline upload; `b02` only adds files (`notes-02.txt`, `cdr-02.csv`, ...) or whole new cases; it never edits a `b01` file. Each case directory is one upload unit.                                                                           |

### 3.4 Per-case content (noise)

| Item                | Noise rule (per case)                                                                                                                                                                                                  |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FIR                 | 3..8 narrative paragraphs; 4..10 persons (accused, complainant, witnesses); 1..4 phones, 0..2 accounts, 0..1 vehicle mentioned                                                                                         |
| Notes               | 2..6 lines                                                                                                                                                                                                             |
| SDR                 | `sdr.csv` in 30% of cases, 1..3 rows                                                                                                                                                                                   |
| Language mix        | `en` 40%, `hi` (Devanagari narrative, Roman identifiers, 60% of person names in Devanagari) 25%, `hi-latn` (romanised Hindi) 25%, `mixed` (Devanagari narrative, Roman names) 10%. Mix is per case and recorded in `manifest.json`, not in `cases.csv`. |
| Phone formats       | 70% plain 10 digits, 10% `+91XXXXXXXXXX`, 10% leading `0`, 10% spaced `90000 14471`. Planted values use the formats recorded in ground truth.                                                                        |
| Case-private noise  | Noise rows written into **planted** cases use identifiers that appear in no other case, so planted fixtures see only planted links.                                                                                    |
| Recurring identity  | 12% of noise persons recur in 2..3 noise cases (true groups): 60% through a shared owned phone, 25% a shared owned account, 15% name, relative and locality only. 6% of noise phones and accounts recur across cases. |
| Look-alikes         | 2% of noise persons are common-name look-alikes of another case's person with a different DOB (true non-links).                                                                                                        |
| Flag material       | Per 50 noise cases at least: 1 HUB number (≥25 distinct counterparties in one case), 2 family or shop SHARED phones, 1 multi-case MULTI_USER account.                                                                  |

| Quarantine          | No planted given name or surname token appears in any noise name, so planted names stay rare and the 1% rule does not turn them common (AC-10 sits exactly on the 45.0 boundary). Pool files list the planted tokens as excluded. |

## 4. Source files

Five kinds per case; only `fir.txt` is mandatory. All headers are English even in Hindi cases.

### 4.1 `fir.txt` (FIR narrative)

Fixed frame, so line numbers are stable and AC-01's "FIR line 12" holds:

| Line | Content                                                                         |
| ---- | ------------------------------------------------------------------------------- |
| 1    | `SYNTHETIC DATA TRACEX-SYN/1 - NOT A REAL RECORD`                               |
| 2    | `FIR No: SYN-<case_id>/<year>`                                                  |
| 3    | `Date of FIR: YYYY-MM-DD`                                                       |
| 4    | `Date of occurrence: YYYY-MM-DD`                                                |
| 5    | `Police Station: <station>`                                                     |
| 6    | `District: <district>`                                                          |
| 7    | `State: <state>`                                                                |
| 8    | `Sections: <invented section list>`                                             |
| 9    | `Complainant: <name>[, <relation and age>]` (no comma when there is no detail)  |
| 10   | blank                                                                           |
| 11   | `NARRATIVE:`                                                                    |
| 12+  | One paragraph per line, English, Devanagari, romanised Hindi or a mix           |

### 4.2 `notes.txt` (officer notes)

Line 1 banner, line 2 `# Officer notes, case <case_id>`, line 3 onward one note per line: `[YYYY-MM-DD] <rank and officer initials>: <text>` (for example `SI RV:`; never a personal name, so a note line names only the people it is about). Notes carry ownership statements, aliases, and "shop number"-type remarks. Later batches add `notes-02.txt` with the same frame.

### 4.3 CSV files

| File          | Columns (exact, in order)                                                                                                                | Notes                                                                                                                                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cdr.csv`     | `call_id,start_time,duration_sec,calling_no,called_no,call_type,cell_id,tower_place`                                                      | `call_id` = `SYN-<case_id>-<n>`; `call_type` ∈ `VOICE`, `SMS`; numbers in any §3.4 format. `tower_place` + the date of `start_time` give the `seen at` pair for co-location (§13 Q5). Sorted by `start_time`, but planted rows are pinned to their stated lines. |
| `bank.csv`    | `txn_id,txn_date,account_no,ifsc,account_holder,direction,counterparty,narration,amount_inr,balance_inr`                                  | One statement account per row group; `account_holder` is the OWNS source for accounts; `direction` ∈ `DR`, `CR`; `counterparty` is a UPI handle (`9000021203@upi`, a phone) or an account number or a name; `ifsc` may be empty (bank unknown). |
| `sdr.csv`     | `msisdn,subscriber_name,relative_name,locality,district,activated_on`                                                                    | SIM subscriber record: the only source of REGISTERED_TO (§13 Q4). Present only where a fixture needs it, plus 30% of noise cases.                                                                                                    |

`tower_place` is the cell of `calling_no` (the calling party), so a `seen at` pair belongs to the calling number. Kit 1.0 writes only 10-digit mobiles in CDR rows; the extractor reports any other number as a malformed row. Landline (STD + number) support in CDR rows is a named follow-up, not in the P2 slice.

The catalogue is the contract between the generator (task 2.1) and the extractor (task 2.2). Ownership is read only from the closed set of patterns documented in the `tracex_engine/extract` package docstring (PR #15). The apposition form needs a separator before the cue: `Mohd. Irfan, mobile ...` or parentheses. A new shape is added to this catalogue and to the extractor in the same change. Planted OWNS lines contain no hedge or negation word (the lists in `tracex_engine/extract/hedges.py`).

Romanised-spelling variant sets used for look-alikes (all fictional pairings): Jaswinder/Jasvinder, Shaikh/Sheikh, Salim/Saleem, Mohammad/Mohd/Md/Muhammad, Irfan/इरफ़ान.

## 8. Ground truth

### 8.1 Files and semantics

`out/<tier>/ground_truth.json`, UTF-8, keys sorted, 2-space indent, generated with the same seed. An engine entity maps to a ground-truth entity when they share at least one `(case_id, file, line, type)` mention and, for PHONE, ACCOUNT and VEHICLE, their normalized forms are equal, or, for PERSON and ORG, their `raw_text` is equal (the text as written, so the mapping does not depend on the transliteration table) (an entity has several mention lines); engine entity ids are never used. Each distinct writing of an entity in a case is its own ground-truth entity; writings of the same real entity in one case are joined by a `within_case` group. An engine entity that matches any member of such a group counts for the group, and an expected link or non-link naming one member is satisfied by any member. The world is **closed**: any cross-case pair not in a same-entity group is a non-link, and an AUTO edge on it is a false positive.

The scorer reads an engine result in the `engine-result/1` format (`data-kit/schema/engine_result.schema.json`). Each PERSON and ORG mention in it carries its own `raw_text`, and every mention is mapped on its own. An engine entity must map into a single `within_case` closure (or one ungrouped entity) of a single case, with every mention mapped; otherwise it fails as `entity_conflict` (gating). Several engine entities inside one closure (a split, for example two transliterations of one name) are allowed.

CONFIRMED stands in for the expected state only when an applied harness step CONFIRMs that link; a link superseded by a later-batch link for the same pair is skipped. Gating.                                                           |
| S2 scores            | `exact`: equal by decimal equality. `band`: recorded, not gating. `exact` is used only where every name pair is an identical normalized name or has no name item: AC-01, 07, 08, 09, 10, 12, 14, 17, 22. |
| S3 non-links         | `ANY_EDGE`: no stored edge in any state, REJECTED and UNDONE included. `AUTO`: edge absent or not AUTO. Gating.                                                                                                         |
| S4 closed world      | No AUTO edge on a pair outside every `cross_case` group. Integrity, on every edge and entity: no `entity_conflict` (§8.1), no self-loop, no edge whose ends are in the same case, at most one edge between two engine entities, no stored AUTO or SUGGESTED edge with band LOW, AUTO only at band HIGH, and no edge in CONFIRMED, REJECTED or UNDONE state without an applied harness step that produced it. Gating, zero tolerance, noise included.                                                                             |
| S5 provenance        | Every `cited_lines` entry appears in the explanation sources; no source outside the two end cases (AC-20).                                                                   |
| S6 reported, not gating | Noise recall (true groups found as AUTO or SUGGESTED), SUGGESTED count on non-link pairs per 100 persons, `oversized_block` count.                                         |

**Kit 1.1 corrections (from the P3.1 and P3.2 reviews).** (1) `cited_lines` of a PERSON or ORG link are the first writing of each entity (the explanation's record), the attribution lines of identifiers both sides are tied to, and any `_extra` lines; a second writing that ties one side to an identifier the other lacks (the P2~P3 phone in the P1~P2 link) is not relied on. Identifier links still cite every mention line of both entities. A REJECTED expectation cites b01 lines only (the edge is frozen). (2) `EL-FX05-PER-B02` expects the AC-05 pair REJECTED after the AC-15 step, with the b01 score, band and gates; `state` may be `REJECTED`, accepted only when the scenario step is applied, and a human step on an expected link covers every expected link on the same pair. A later-batch link whose harness is not applied does not supersede the earlier one. (3) `EL-ACC-E1E7`, `E3E7` and `E8E7` expect G6 `cluster_same_case` as well as G1 (E-7 sits in C-201, which already holds an AUTO-linked `9000014471`). (4) Noise phones are never one adjacent-digit swap apart, so only the planted transposed pairs read as `PHONE_TRANSPOSED` (S6 `suggested_on_non_link_pairs` is 0).

**Deferred links (kit 1.1).** `score` takes a list of expected-link ids that may wait for a later engine tier (`--defer`, `--defer-file`). A named link that is missing, or whose every failure is "not there yet" (state, band or score at or below the expected one; evidence kinds, gates or cited lines absent), is reported under `deferred` and counted as `deferred` in the S1, S2 and S5 totals, never as passed; `ok` ignores it. A deferred link stored above its expected state, band or score, or citing a source outside its end cases, fails as usual. S3 non-links, S4 closed world and integrity, and forbidden trap hits are never deferrable. A deferred link that passes is reported `passing` so it can be taken off the list.

The result's `batches_loaded` is `["b01"]` or `["b01","b02"]`; any other value is an input error, not a test failure. The scenario-only acceptance cases (AC-16, 18, 20, 23, 24, 25, 27) are reported as not scored; the engine task (P2.4) covers each with its own tests, and its end-to-end gate is the scorer passing on b01 and on b01+b02 plus those tests.

## 10. Determinism

| Rule        | Statement                                                                                                                                                                                                                           |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Seed        | Default seed `20260401`, flag `--seed`; the golden hash is for the default. A sub-stream per purpose: `random.Random(int.from_bytes(sha256(f"{seed}:{purpose}").digest()[:8]))`, never the global generator, never `hash()`. Choices are derived from `getrandbits` only (method algorithms of `random.Random` are not guaranteed across Python versions); the golden hash is pinned to Python 3.12 (CODEBASE_RULES).      |
| No ambient  | No wall clock (fixed "today" `2026-10-31`), no `uuid4` (`uuid5` from stable names), no locale, no OS-order directory listing (sorted), no floating point in output text.                                                            |
| Byte-equal  | Same kit version and seed give byte-identical files on any OS (LF, UTF-8, NFC, sorted keys). `manifest.json` lists sha256 per file; `golden/<tier>.sha256` holds the manifest hash.                                                  |
| Stability   | Planted content does not depend on tier: values, lines and ground truth entries for planted fixtures are identical in `small` and `demo`. Adding noise never moves a pinned line.                                                  |
| Dependencies | Standard library only; name pools are committed files (no Faker, no network).                                                                                                                                                       |
| Pools       | Changing a pool file or this spec's planted values bumps `kit_version` and regenerates the golden hash in the same PR.                                                                                                              |
